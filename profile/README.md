## Open Health Technology Foundation

A neutral, long-term home for open-source health software.

<br clear="left">

Software that health care depends on should be open, free from the control of any single vendor, and maintained in public. OHTF stewards that software: clinical terminologies, identifier and terminology tooling, clinical calculators and charting components. Every Foundation Project has open code, named maintainers, a security contact and a clear lifecycle status, held by an organisation that outlasts any one employer.

OHTF is Open Health Technology CIC, a community interest company registered in England and Wales, company number [17544421](https://find-and-update.company-information.service.gov.uk/company/17544421).

### Foundation Projects

| Project | What it does |
| --- | --- |
| [`oct`](https://github.com/ohtf/oct) | Open Clinical Terminology: an open, community-owned clinical terminology. |
| [`nhs-number-py`](https://github.com/ohtf/nhs-number-py) | Validate, normalise, format and generate NHS Numbers in Python. |
| [`clincalc`](https://github.com/ohtf/clincalc) | Open, auditable clinical calculators: one Rust engine behind a CLI, Python package, MCP tool and API. |
| [`digital-pews`](https://github.com/ohtf/digital-pews) | An EPR-agnostic charting and scoring component for the National Paediatric Early Warning System, with SMART on FHIR. |

More projects, and how to bring one to OHTF: [openhealthtechnology.org/projects](https://openhealthtechnology.org/projects/).

### Get involved

- **Use the projects** and report what breaks. Issues on the project's repository are the fastest route.
- **Contribute** code, tests, documentation or clinical review. Start with the [contributing guide](https://openhealthtechnology.org/community/). Sign off your commits (`git commit -s`).
- **Stay up to date** by joining the [mailing list](https://openhealthhub.org/t/open-health-technology-foundation-cic-start-here-join-the-mailing-list/3094) on Open Health Hub.
- **Report vulnerabilities privately**, never in a public issue: see the [security policy](https://openhealthtechnology.org/community/security/).

Never include real patient data in any issue, pull request, test fixture or log.
